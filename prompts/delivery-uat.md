User acceptance tests (UAT) run on every PR head you push, before its Claude Code review. You start them with `uat-test`; the deployment's UAT gate runs them, independently of you, and publishes the `superagent/uat` check through its own GitHub App; that check is the only authority on UAT. Never post a status or check named `superagent/uat`, never edit, add or remove an issue's `## User Acceptance Tests` section, never change a test's expected outcome to make it pass, and never state UAT results you did not get from `uat-test`.
In "Review the PR's current head", between steps 1 and 2: in the ticket directory, run `uat-test $DSH_SUPERAGENT_GITHUB_REPOSITORY <number> <sha>` as a background job and end your turn; its end wakes you with its output. It asks the gate to test <sha>, waits for the verdict and prints the report: the verdict, each failing scenario with what was expected, what was observed and how to reproduce it, and the UAT run id. Its output ends with the path of a file holding the whole report and a last line `uat-test: PASS|NOT_REQUIRED|FAIL|BLOCKED for <sha>`; read that whole file. `uat-test --artifact <run id> <path>` prints a file the run kept, such as `app-logs/app.log`, `setup.log` or the evidence under `tester-work/attempt-1/artifacts/`.
- Exit status 0 is a pass, or no UAT for this issue, for <sha>: continue with step 2 for the same <sha>. Never run `claude-review` on a head whose `uat-test` did not exit 0.
- 1 is a fail: fix the application so that every failing scenario behaves as the issue expects, run what reproduces it, push and review the new head from step 1; the new head is tested again in full. A report that says the PR cannot be tested (no `Closes #<n>` line, `.superagent/uat.yaml` missing or invalid, the setup or start command failing) is fixed in the PR the same way.
- 2 is blocked (a scenario could not be run, the issue's UAT section is invalid, the environment is not allowed, the runner is unavailable, or the PR used up its three failing UAT rounds): run it once more for the same <sha> when the report names the runner or the gate; otherwise, or if it is blocked again, report blocked with the report's reasons and never merge.
- Any other status is no verdict: run it once more for the same <sha>, and if that is not 0, 1 or 2 either, report blocked with its message.
A failed Claude Code review that leads to a new commit is a new head: it gets `uat-test` again before the next review. A PR gets at most three failing UAT rounds, counted by the gate across heads and restarts, separately from its three failed reviews. Record each UAT <sha>, run id and result in orchestrator_report.
Before merging, right after reading the head and title again, run `uat-test --verify $DSH_SUPERAGENT_GITHUB_REPOSITORY <number> <reviewed sha>`; merge only when it exits 0, and `superagent/uat` is one of the required checks that must have passed. When it exits 1 (the issue's UAT or the environment changed since the pass), run `uat-test` for that head again and continue from its result.
